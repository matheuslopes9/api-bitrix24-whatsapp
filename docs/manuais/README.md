Documentação **para quem usa** o UC Talk, não para quem o desenvolve.

## Como estes documentos se diferenciam do resto de `docs/`

- [`docs/fluxos/`](../fluxos) e [`docs/aprendizados/`](../aprendizados) explicam
  **como o sistema funciona por dentro** e por que ficou assim. Público: quem
  mexe no código.
- `docs/manuais/` explica **o que fazer na tela**. Público: quem opera.

Os dois manuais são organizados por **sintoma** e por **tarefa**, não por
funcionalidade — é assim que a pessoa chega até eles: com um problema na mão ou
algo para fazer, não com vontade de conhecer o menu.

## Ao alterar uma tela

Se você mudar o nome de uma aba, a etiqueta de um estado ou o texto de um botão,
atualize o manual correspondente na mesma alteração. Manual que descreve uma
tela que não existe mais é pior que manual nenhum: ele manda a pessoa procurar
algo que não vai achar, e ela conclui que o problema é ela.

Os pontos mais sensíveis a essa defasagem:

- as três etiquetas de sessão (**online**, **offline**, **desvinculado**) — a
  ação de cada uma é diferente, e é o que o suporte mais consulta;
- os benefícios da licença, que controlam quais abas o cliente enxerga;
- os botões de **Ferramentas**, um a um.
